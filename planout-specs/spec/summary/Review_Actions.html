1.  COMPONENTS
1.1Overview

The Review Actions bar is a navigation and utility tool located at the top of the document review page. Its primary purpose is to provide clear context about the document you are currently viewing and to offer a simple way to compare different versions of that document side-by-side. This ensures that reviewers always have the necessary information at their fingertips to make informed decisions during the document lifecycle.

1.2Step-by-Step Flow
1.Document Identification: The bar displays the document name and its unique identification number (ICF ID) so you can immediately confirm which file is open.
2.Version Awareness: The current version of the document (e.g., "v1.0 Draft") is clearly displayed, ensuring you are aware of the specific iteration you are reviewing.
3.Version Comparison: By clicking the "Compare Versions" button, the system retrieves a list of all available versions for that document. You can select any previous or alternative version from the dropdown menu to open it alongside your current view for a direct comparison.
1.3Key Concepts
–ICF ID: A unique identifier for the Informed Consent Form, used to ensure accuracy and traceability across different document versions.
–Version Label: A status indicator that tells you exactly which stage of the document lifecycle you are looking at, such as a draft or a finalized version.
–Side-by-Side Comparison: A feature that allows you to view two different versions of a document simultaneously, making it easier to spot changes, updates, or discrepancies.
1.4Business Value

This feature streamlines the review process by eliminating the need to manually search for document history or toggle between different browser tabs. By providing instant access to version history and comparison tools, it reduces the risk of human error, saves time for reviewers, and ensures that the most current and accurate information is always being used for compliance and decision-making.

2.  Logic
2.1Overview

The Review Actions feature allows users to easily compare different iterations of a document. By selecting a document, the system automatically retrieves a complete history of its versions, enabling users to see how the content has evolved over time and identify which version is currently active.

2.2Step-by-Step Flow
1.The user initiates the "Compare Versions" action from the document review page.
2.The system identifies the specific document and requests its full version history.
3.The system retrieves the list of all available versions, including their labels, current status, and whether they are the active version.
4.This information is sent back to the interface to populate a dropdown menu, allowing the user to select and compare specific versions.
5.If no versions are found, the system displays an empty list; if an error occurs during the request, the system notifies the user that the information could not be retrieved.
2.3Key Concepts
–Version History: A chronological list of all saved iterations of a document, allowing for easy tracking of changes.
–Active Version: The current, primary version of the document that is officially in use or under review.
–Version Status: The current state of a specific document iteration (e.g., draft, pending, or finalized).
2.4Business Value

This feature streamlines the review process by eliminating the need to manually search for document updates. By providing a clear, accessible list of versions, it ensures that stakeholders are always reviewing the correct information, reduces the risk of working on outdated drafts, and improves overall document governance and transparency.
