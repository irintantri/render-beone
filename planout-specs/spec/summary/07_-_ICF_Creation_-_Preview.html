1.  Frontend
1.1Overview

The ICF Preview feature provides a final "read-only" view of the Informed Consent Form (ICF) before it is officially issued. This screen allows users to verify the document's layout, content, and structure in a simulated PDF format, ensuring everything is accurate before the final publication.

1.2Step-by-Step Flow
1.Loading: When the user navigates to the preview page, the system automatically retrieves the document details and all associated sections, organizing them in the correct order.
2.Review: The document is displayed on a simulated PDF page. Users can view the full content, including the title, protocol metadata, and all numbered sections.
3.Adjustment: A toolbar at the top allows users to view the document filename and page count, as well as zoom in or out to inspect specific details.
4.Navigation: If the user identifies any errors, they can select the "Back to Review" button to return to the previous editing stage.
5.Publication: Once the user is satisfied, they click the "Publish" button. Upon success, the button is replaced by a confirmation badge, indicating the document is now officially published.
1.3Key Concepts
–Simulated PDF View: A visual representation of the final document that mimics how the printed or exported file will look, allowing for a final quality check.
–Document Sections: The individual components of the ICF (such as study objectives, risks, or participant rights) that are pulled together and displayed in their specific, logical order.
–Publishing: The final action that locks the document content and marks it as officially issued within the system.
–Review Stage: A safety gate that allows users to navigate backward to correct any typographical or formatting errors before the document is finalized.
1.4Business Value

This feature acts as the final quality assurance gate in the ICF creation process. By providing a realistic preview, it reduces the risk of errors in sensitive legal and medical documentation. It gives users the confidence that the document is formatted correctly and ready for distribution, while the "Back to Review" functionality ensures that any last-minute corrections can be made easily without disrupting the workflow.

2.  Logic
2.1Overview

The ICF (Informed Consent Form) Preview and Publication feature allows users to review a document in a simulated PDF format before finalizing it. This ensures that the document content, structure, and metadata are accurate and ready for distribution. Once the user is satisfied with the preview, they can officially publish the document, which locks the content and records the exact date and time of publication.

2.2Step-by-Step Flow
1.Data Retrieval: When you open the preview page, the system automatically gathers all necessary information, including the document’s title, version, and status, as well as the specific content sections that make up the document.
2.Document Simulation: The system uses this retrieved data to generate a simulated PDF view, allowing you to see exactly how the document will appear to the end user.
3.Final Review: You review the document to ensure all information is correct and that it has passed any required approval checks.
4.Publication: Once approved, you trigger the publish action. The system saves the document as "Published" and attaches a permanent timestamp to record when the final version was created.
5.Confirmation: Upon a successful publish, the interface updates to display a confirmation badge, indicating the document is now live and finalized.
2.3Key Concepts
–ICF (Informed Consent Form): The core document being managed, which requires a formal review and publication process.
–Preview: A simulated view of the document that allows users to verify the layout and content before it is officially released.
–Metadata: The background information about the document, such as its title, current version, and status, which helps identify and track the file.
–Publication: The final step in the document lifecycle that locks the content and marks it as official, accompanied by a timestamp for audit purposes.
2.4Business Value

This feature provides a reliable "what-you-see-is-what-you-get" experience, reducing the risk of errors in sensitive consent documentation. By automating the publication timestamp and locking the document upon release, the system ensures data integrity and maintains a clear, auditable history of when each version of a document was finalized.
