1.  Frontend
1.1Overview

The ICF Preview and Publishing feature provides a final "read-only" view of the Informed Consent Form (ICF) before it is officially finalized. This screen allows users to review the document exactly as it will appear in its final format, ensuring all content, headers, and protocol metadata are correctly organized. Once satisfied, the user can publish the document, which locks the content and marks it as complete.

1.2Step-by-Step Flow
1.Document Loading: Upon entering the page, the system automatically retrieves the document’s metadata and all associated content sections.
2.Visual Review: The document is displayed in a simulated PDF layout, showing the organization header, title, and all numbered sections in their final order.
3.Document Controls: Users can use the toolbar to view the document title and page count, or adjust the view using zoom controls to inspect specific details.
4.Publishing: Once the user confirms the document is correct, they click the "Publish" button.
5.Confirmation: Upon a successful publish, the button is replaced by a success badge, indicating the document is now locked and finalized.
6.Navigation: If the user identifies any errors during the preview, they can select the "Back to Review" button to return to the previous editing stage.
1.3Key Concepts
–Simulated PDF View: A digital preview that mimics the final printed document layout, allowing users to verify formatting before finalization.
–Publishing: The final action that locks the document content, preventing further edits and creating an official record of the ICF.
–Document Toolbar: A utility area that provides context (such as file name and page count) and viewing tools (zoom) to assist in the review process.
–Progress Stepper: A visual indicator that helps the user understand their current position within the overall ICF creation workflow.
1.4Business Value

This feature acts as the final quality assurance gate in the ICF creation process. By providing a high-fidelity preview, it reduces the risk of errors in sensitive legal and medical documentation. The ability to lock the document upon publishing ensures data integrity and provides a clear, auditable status for the document, giving stakeholders confidence that the final version is accurate and ready for distribution.

2.  Logic
2.1Overview

The ICF Preview and Publish feature allows users to review a generated Informed Consent Form (ICF) in a simulated document format before finalizing it. This feature ensures that all document details and content sections are accurately displayed for a final check. Once the user is satisfied with the preview, they can trigger the publishing process, which officially locks the document and records the completion time.

2.2Step-by-Step Flow
1.Document Loading: When you open the preview page, the system automatically retrieves the document’s background information (such as the title and creation date) and all its specific content sections.
2.Review: The system combines this information to display a clear, readable version of the ICF on your screen.
3.Publishing: Once you have reviewed the document and are ready to finalize it, you click the "Publish" button.
4.Finalization: The system sends a request to officially mark the document as published.
5.Confirmation: Upon a successful update, the system replaces the "Publish" button with a "ICF Published Successfully" badge, confirming that the document is now locked and timestamped.
2.3Key Concepts
–Document Metadata: The high-level information about the form, such as its title, current status, and when it was created.
–Section Content: The specific text and data blocks that make up the body of the Informed Consent Form.
–Publishing: The final action that transitions the document from a draft state to a permanent, finalized record.
–Status Badge: A visual indicator in the user interface that provides immediate feedback on whether the document has been successfully published.
2.4Business Value

This feature provides a "safety net" for users by allowing them to verify the accuracy of the ICF before it is officially recorded. By separating the preview and publishing steps, the system reduces the risk of errors, ensures compliance through a formal publishing process, and provides clear visual confirmation once a document is finalized.
