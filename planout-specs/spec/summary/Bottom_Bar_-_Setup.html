1.  COMPONENTS
1.1Overview

The "Bottom Bar - Setup" feature provides a consistent navigation and action area at the bottom of the Setup page. It is designed to guide users through the final steps of preparing an Informed Consent Form (ICF) by ensuring all necessary information is provided before starting the generation process. It also offers a simple way for users to exit the setup process and return to their main dashboard.

1.2Step-by-Step Flow
1.Validation: The system checks that you have selected a protocol, chosen a template, and attached at least one reference document.
2.Activation: Once all three requirements are met, the "Generate ICF" button becomes active.
3.Generation: Clicking the button triggers the system to begin creating the ICF draft based on your selections.
4.Progress Tracking: The application moves to a dedicated screen that displays the real-time progress of the generation process through six sequential checkpoints.
5.Completion: Once the system finishes the generation, it automatically transitions you to the editor to review the final document.
6.Navigation: At any point during the setup, you can use the "Back to Dashboard" button to exit the current page and return to your main workspace.
1.3Key Concepts
–Generate ICF Button: A smart action button that remains disabled until the user has provided all required inputs, preventing errors during the document creation process.
–Generation Pipeline: An automated background process that parses your selected protocol and template to build the ICF draft.
–Progress Visualization: A user-friendly display that shows exactly where the system is in the six-step generation process, providing transparency while the AI works.
–Ghost Button: A secondary navigation element used for the "Back to Dashboard" option, designed to be less prominent than the primary action button to keep the user focused on the main task.
1.4Business Value

This feature streamlines the ICF creation workflow by enforcing data quality at the source. By requiring all necessary components (protocol, template, and references) before allowing generation, the system reduces the likelihood of errors or incomplete documents. Furthermore, the real-time progress tracking improves the user experience by providing clear feedback during the automated generation process, ultimately saving time and increasing confidence in the final output.

2.  logic
2.1Overview

The "Generate ICF" feature allows users to initiate the creation of an Informed Consent Form (ICF) draft directly from the Setup page. By clicking a single button, the system captures the necessary protocol information, triggers a background process to analyze the document template, and prepares the data for further processing. This automation removes the need for manual document structuring, ensuring that the ICF is ready for review quickly and accurately.

2.2Step-by-Step Flow
1.Initiation: The user clicks the "Generate ICF" button on the Setup page, which sends the relevant protocol and template information to the system.
2.Job Creation: The system creates a new background task to track the generation request and assigns it a unique identifier.
3.Document Extraction: The system automatically reads the raw text from the selected document template.
4.Logical Structuring: The system analyzes the extracted text to identify specific sections, logical structure, and key results.
5.Pipeline Handoff: Once the document is organized, the structured data is passed to the next stage of the workflow for final processing.
6.Confirmation: The system returns a confirmation to the user, providing the unique job ID and protocol ID to verify that the process has successfully started.
2.3Key Concepts
–Informed Consent Form (ICF): A critical document that outlines the details of a study for participants; this feature automates its initial drafting.
–Background Job: A process that runs behind the scenes, allowing the system to handle complex document analysis without freezing the user interface.
–Systematic Parsing: The intelligent process of reading a document and breaking it down into organized, usable data points rather than just raw text.
–Downstream Pipeline: The subsequent stages of the software that take the organized document data and perform further actions, such as final formatting or review.
2.4Business Value
–Efficiency: Reduces the time spent manually formatting and structuring consent forms, allowing staff to focus on higher-value tasks.
–Consistency: Ensures that every ICF is parsed and structured using the same logical rules, reducing the risk of human error.
–Scalability: By automating the document intake process, the system can handle a higher volume of protocol setups without requiring additional manual oversight.
3.  Data
3.1Overview

The "Setup" bottom action bar feature introduces a streamlined way for users to initiate data generation tasks. When a user triggers a generation request from the Setup page, the system immediately acknowledges the request, creates a tracking record, and provides a unique reference so the user can monitor the progress of their task in real-time.

3.2Step-by-Step Flow
1.Request Initiation: The user triggers a generation request from the Setup page.
2.Validation: The system checks that all necessary information (specifically the protocol identifier) is present and valid. If information is missing, the system alerts the user that the request cannot be processed.
3.Task Creation: Once validated, the system creates a new "pending" job record in the background to track the work.
4.Confirmation: The system sends an immediate confirmation back to the interface, providing a unique Job ID and echoing the Protocol ID to confirm exactly what is being processed.
5.Live Monitoring: The system uses the provided Job ID to open a live connection, allowing the interface to receive real-time updates as the generation task progresses.
3.3Key Concepts
–Job ID: A unique digital fingerprint assigned to every generation request, allowing the system to track and report on that specific task.
–Protocol ID: A reference label that identifies the specific set of instructions or parameters the system should use for the generation task.
–Pending Status: The initial state of a task, indicating that the system has successfully received the request and is preparing to start the work.
–Real-time Stream: A live communication channel between the server and the user's screen, ensuring the user sees progress updates as they happen without needing to refresh the page.
3.4Business Value

This feature improves the user experience by providing immediate feedback when a task is started. By confirming the request and establishing a live connection, users are never left wondering if their action was successful. This transparency reduces uncertainty and allows users to manage their workflow efficiently while the system handles complex generation tasks in the background.
