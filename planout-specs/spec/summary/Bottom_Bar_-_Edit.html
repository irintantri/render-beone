1.  components
1.1Overview

The "Bottom Action Bar" is a navigation and control component located at the bottom of the "Edit and Refine" page. It provides users with clear options to either finalize their work by submitting it for review or to return to the initial setup phase if further adjustments are needed.

1.2Step-by-Step Flow
1.Submit for Review: When the user clicks the "Submit for Review" button, the system sends the document to be processed.
2.Status Update: Upon a successful submission, the document’s status is automatically updated to "In Review."
3.Navigation to Review: Once the status is updated, the user is automatically redirected to the "ICF Review" page to view the document in its new state.
4.Error Handling: If the submission fails due to a system error or invalid document data, the user is notified with an error message.
5.Back to Setup: If the user clicks the "Back to Setup" button, they are immediately navigated back to the "ICF Creation - Setup" page to modify their protocol or configuration settings.
1.3Key Concepts
–Submit for Review: A primary action that triggers the transition of a document from a draft state to an "In Review" state.
–Back to Setup: A secondary navigation action that allows users to exit the editing process and return to the configuration wizard.
–Ghost Button: A visual style used for the "Back to Setup" button to indicate it is a secondary action, keeping the focus on the primary "Submit" button.
–Status Transition: The automated process where the system changes the document's internal status based on user interaction.
1.4Business Value

This feature streamlines the document workflow by providing immediate, context-aware actions. By placing these controls at the bottom of the screen, users can easily transition between editing, reviewing, and setup phases without searching for navigation options. This reduces friction in the document creation process and ensures that document statuses are updated accurately and automatically, minimizing manual administrative tasks.

2.  logic
2.1Overview

The "Submit for Review" feature provides a simple, one-click action on the Edit and Refine page that allows users to finalize their work and move a document into the formal review process. This ensures that once a user is satisfied with their edits, they can easily signal to the system that the document is ready for the next stage of the workflow.

2.2Step-by-Step Flow
1.The user clicks the "Submit for Review" button located in the bottom navigation bar.
2.The system receives the request and identifies the specific document being edited.
3.The system automatically updates the document's status to "In Review."
4.The system confirms the update is successful, signaling that the document has been moved out of the editing phase.
5.If the document cannot be located, the system will notify the user that the action could not be completed.
2.3Key Concepts
–Submit for Review: A trigger action that transitions a document from an "Editing" state to an "In Review" state.
–Document Status: A tracking label that tells the system and other users exactly where a document is in its lifecycle.
–In Review: The designated status that indicates a document is no longer being actively edited and is awaiting further action or approval.
2.4Business Value

This feature streamlines the transition between editing and approval, reducing manual administrative work. By automating the status update, it ensures that document tracking remains accurate and that stakeholders are immediately aware when a document is ready for their attention, ultimately speeding up the overall review cycle.

3.  Data
3.1Overview

The "Bottom Bar - Edit" feature provides a streamlined way for users to finalize their work on the "Edit and Refine" page. When a user is satisfied with their document, they can trigger a submission process directly from the bottom action bar. This action officially moves the document into the review cycle, ensuring that the system tracks the document's progress and maintains an accurate audit trail.

3.2Step-by-Step Flow
1.The user initiates the submission process from the bottom action bar on the document editing page.
2.The system locates the specific document being edited using its unique identifier.
3.The system verifies that the document is eligible for submission (e.g., ensuring it hasn't already been archived).
4.The document’s status is updated to "In Review" to reflect that it is ready for approval.
5.The system records the exact time of this update to keep the document's history current.
6.An audit log entry is automatically created to document the status change for compliance and tracking purposes.
3.3Key Concepts
–Status Update: The process of changing a document's state from "Draft" (or similar) to "In Review," signaling that the editing phase is complete.
–Audit Log: A secure, chronological record of changes made to a document, which provides transparency and accountability for all status transitions.
–Validation: A safety check performed by the system to ensure that a document is in a valid state before allowing it to move to the review stage.
–Last Modified Timestamp: A system-generated record that tracks the most recent time a document was updated, ensuring users always know when the latest change occurred.
3.4Business Value

This feature simplifies the transition from document creation to the approval process. By automating the status update and audit logging, it reduces manual administrative work, minimizes the risk of human error, and ensures that all stakeholders have clear visibility into which documents are ready for review. This creates a more efficient and reliable workflow for managing document lifecycles.
