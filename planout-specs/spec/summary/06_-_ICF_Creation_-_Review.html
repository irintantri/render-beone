1.  Frontend
1.1Overview

The ICF Review feature provides a centralized workspace for stakeholders to evaluate draft Informed Consent Forms (ICFs). It allows reviewers to read the document, view feedback, track the history of changes, and perform final approval or rejection actions. The interface is designed to provide transparency by clearly distinguishing between human-authored content and AI-generated sections.

1.2Step-by-Step Flow
1.Document Loading: Upon opening the review page, the system retrieves the full document content and the complete history of actions taken on that document.
2.Navigation and Context: The user is presented with a header and a progress tracker to maintain context regarding the document’s protocol and current stage in the workflow.
3.Document Review: The document is displayed in a structured format, with each section presented as an individual card. Sections generated by AI are clearly labeled with a visual badge.
4.Feedback and History: A side panel provides access to comments and a chronological "Audit Trail," which lists every significant action (such as edits or previous reviews) taken on the document.
5.Decision Making: Using the review actions bar, the reviewer can compare different versions of the document to see what has changed and then formally approve or reject the draft.
1.3Key Concepts
–Audit Trail: A comprehensive, time-stamped log of all activities related to the document, ensuring full accountability and traceability for compliance.
–Section Cards: A modular way of displaying the document, where each part of the ICF is broken down into a readable, organized block.
–AI-Generated Badge: A visual indicator that helps reviewers quickly identify which parts of the document were drafted by AI, allowing them to focus their scrutiny appropriately.
–Version Comparison: A tool that allows reviewers to see the differences between document drafts, making it easier to verify that feedback has been correctly incorporated.
1.4Business Value

This feature streamlines the document approval process by providing a single source of truth for reviewers. By integrating the audit history, comment threads, and version comparison tools directly into the review interface, the system reduces the time spent switching between different platforms. Furthermore, the clear labeling of AI-generated content and the detailed audit trail support regulatory compliance and quality assurance, ensuring that all changes are transparent and documented.

2.  Logic
2.1Overview

The ICF Review feature provides a dedicated workspace for stakeholders to examine draft Informed Consent Forms (ICFs). This interface allows reviewers to view the current version of a document alongside a complete history of all actions taken on it. By combining the document content with a transparent audit trail, the system ensures that reviewers have the necessary context to provide feedback and track the document's progress toward finalization.

2.2Step-by-Step Flow
1.Document Loading: When a user opens the Review Page, the system retrieves the full document, including its current content, version information, and status.
2.Content Display: The document is rendered in the center panel, allowing the reviewer to read the text and evaluate the draft.
3.Audit Trail Retrieval: Simultaneously, the system fetches a chronological list of all activities associated with that specific document.
4.History Presentation: The audit trail is displayed to the user, showing a clear record of who performed specific actions and when those actions occurred.
2.3Key Concepts
–ICF (Informed Consent Form): The core document being reviewed, which contains the specific protocol details and consent language for a study.
–Audit Trail: A chronological, tamper-evident log that tracks the lifecycle of the document, including review comments, status changes, and user interactions.
–Document Metadata: Supporting information about the file, such as its version number, creation date, and last modification timestamp, which helps reviewers verify they are looking at the correct draft.
2.4Business Value
–Improved Accuracy: By providing a clear view of the document and its history, reviewers can easily identify previous feedback and ensure that requested changes have been incorporated.
–Regulatory Compliance: The detailed audit trail provides full traceability, which is essential for maintaining compliance and accountability throughout the document approval process.
–Efficiency: Centralizing the document content and the history of actions in one view reduces the time spent searching for context, allowing for a faster and more informed review cycle.
3.  Data
3.1Overview

The ICF Review feature allows users to access a draft version of an Informed Consent Form (ICF) to evaluate its content. It provides a dedicated workspace where reviewers can see the current document alongside a history of previous actions and feedback. This ensures that the document can be refined iteratively based on reviewer comments until it is ready for finalization.

3.2Step-by-Step Flow
1.Accessing the Review Workspace: When a user opens a document for review, the system retrieves the current version of the ICF content and its associated metadata.
2.Viewing the Audit Trail: Simultaneously, the system pulls a chronological list of all past actions taken on that document. This history is displayed from newest to oldest, allowing the reviewer to quickly catch up on recent changes or feedback.
3.Reviewing and Incorporating Feedback: The reviewer examines the document content and the activity history to identify necessary adjustments.
4.Updating the Document: Once the reviewer makes the required changes, the system saves the updated content and metadata. The document’s "last modified" timestamp is automatically updated to reflect that a new iteration has been created.
3.3Key Concepts
–Audit Trail: A chronological record of all activities performed on a document, helping users track the history of changes and feedback.
–Document Metadata: Descriptive information about the ICF, such as its version number and status, which helps keep the document organized.
–Iterative Updates: The ability to modify and save the document multiple times, ensuring that feedback is captured and reflected in the latest version.
3.4Business Value

This feature streamlines the document approval process by centralizing the review and editing tasks. By providing a clear history of feedback, it reduces the risk of miscommunication between stakeholders and ensures that all requested changes are accurately incorporated. This leads to higher quality documentation and a more efficient path toward finalizing the ICF.
